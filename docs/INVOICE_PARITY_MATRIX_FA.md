# قرارداد برابری امکانات فاکتورهای الماس در ویندوز (WPF)
**شناسه قرارداد:** `ALMAS-INVOICE-PARITY-v1`  
**مبنای مقایسه:** فایل‌های واقعی `almas_invoice_core 0.3.91` و `almas_desktop_bridge 0.1.8`، تصویرهای ارسالی کاربر و سورس `AlmasCashierDesktop 0.3.0`.  
**قاعده:** وضعیت «موجود» فقط وقتی مجاز است که UI بومی، داده واقعی و آزمون عملکرد (و مجوز) برای آن وجود داشته باشد. صرف نمایش یک دکمه، قابلیت کامل نیست.

## راهنمای وضعیت
- ✅ «بومیِ خواندنی»: کد و داده واقعی دارد؛ لازم است روی هاست و ویندوز کاربر آزمایش شود
- 🟡 «بخشی»: بخش بومی هست اما امکانات یا تأیید سرور ناقص است
- ⛔ «در انتظار»: در ویندوز وجود ندارد یا هنوز عملیاتی/امن نیست
- 🔒 «سرور-الزامی»: تنها با منطق رسمی سرور قابل فعال‌سازی است؛ نباید در WPF قیمت یا موجودی قطعی حدس زده شود

## D. الزامات غیرقابل‌مذاکرهٔ معماری
1. **UI کاملاً WPF** برای فهرست، جزئیات، صدور، جستجو و مدیریت مشتری؛ WebView2 جایگزین فرم‌های فروش نمی‌شود.
2. **یک منبع حقیقت:** AIC برای فاکتور، SCR برای قیمت/تخفیف، `almas_warehouse` برای موجودی قابل فروش. موجودی قدیمی/داده نمایشی هرگز وارد محاسبه نمی‌شود.
3. **دسترسی مبتنی بر عملیات، نه کلید نمایشی:** کلید دستگاه برای API خواندنی کافی نیست؛ ثبت مالی نیازمند سازوکار احراز هویت و مجوز نوشتن با ثبت رویداد است.
4. **ثبت اتمیک و بدون تکرار:** شماره، پرداخت، رزرو و عملیات صندوق یکپارچه و idempotent؛ قطع شبکه نباید فاکتور یا پرداخت نیمه‌کاره ایجاد کند.
5. **بدون ادعای ساختگی:** هیچ دکمه‌ای به عنوان «عملیات کامل» معرفی نمی‌شود تا نتیجه واقعی سرور یا سرویس رسمی تأیید شود.
6. هر تغییر در فرم وب یا موتور قیمت‌گذاری باید در این ماتریس ثبت شود و وضعیت WPF مجدداً بررسی شود.
7. معیار تحویل هر قابلیت: UI بومی + API منبع رسمی + مجوز + پیام خطا + آزمون مثبت/منفی + عدم تأثیر بر سایر بخش‌ها.

## E. ترتیب اجرا و جلوگیری از فراموشی
- **مرحله ۱:** قرارداد کامل داده فهرست و جزئیات + وضعیت‌ها/KPI/فیلتر/چاپ. اولویت کاربردی بالا.
- **مرحله ۲:** جستجوی وابسته و رسمی مشتری، کاتالوگ کلکسیون/رنگ/اندازه/کد، نمایش موجودی قابل فروش.
- **مرحله ۳:** سرویس Quote رسمی نوع فروش، متراژ، تخفیف پایه/ارگانی/سقف و تعدیل، با آزمون تطبیقی علیه وب.
- **مرحله ۴:** ثبت و ویرایش واقعی با ACL، رزرو و عدم‌تکرار.
- **مرحله ۵:** پرداخت، صندوق، استرداد، لغو، مرجوعی، چاپ/اشتراک، ورود و پرداخت گروهی.

**پروتکل اعتبارسنجی:** برای هر شناسه `Lxx/Fxx/Dxx` هنگام پیاده‌سازی یک آزمون `Given/When/Then` ثبت می‌شود. تغییر وضعیت فقط بعد از تست ممکن است. این سند باید همراه با سورس نگهداری شود و هر انتشار نسخه با آن گزارش اختلاف بدهد.
