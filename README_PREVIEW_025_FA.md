# Almas Cashier Desktop — نسخه 0.2.5 (مرحله نخست عملیات فروش)

## مبنای توسعه
سورس WPF نسخه 0.2.4 در شاخه `feat/native-dashboard-0.2.0`. نسخه جدید در شاخه `feat/sales-operations-0.2.5`.

## تغییرات
- داشبورد بومی WPF و جدول خواندنی فاکتورها محفوظ مانده است.
- دکمه‌های ایجاد فاکتور، دریافت و چاپ در حالت متصل از وضعیت آزمایشی خارج شده‌اند و به فرم واقعی سامانه هدایت می‌شوند. ثبت نهایی طبق همان منطق و مجوزهای سامانه وب است.
- کنار فهرست‌های خواندنی فروش و حسابداری، دکمه «باز کردن فرم عملیاتی واقعی» اضافه شده است.
- منوی «مرکز مدیریت انبار» برای دستگاه متصل به مدیر، با نصب پل `almas_desktop_bridge 0.1.7` از سرور دریافت می‌شود؛ صفحات انبار به پنل عملیاتی HTTPS هدایت می‌شوند.
- ورود به پنل وب در مرورگر داخلی WebView2 مستقل از کلید دستگاه است؛ کلید دستگاه فقط برای API خواندنی و در حافظه برنامه استفاده می‌شود.
- پنل عملیاتی تنها HTTPS و همان دامنه تنظیم‌شده را می‌پذیرد؛ انتقال به HTTP یا دامنه دیگر مسدود می‌شود. کوکی‌های مرورگر هنگام قطع اتصال یا بستن برنامه پاک می‌شوند.
- در تنظیمات، نشانی جداگانه «پنل عملیاتی HTTPS» قابل تعیین است تا آدرس پنل وب با درگاه API اشتباه گرفته نشود.

## نصب و آزمایش
1. از نسخه فعلی برنامه پشتیبان تهیه کنید؛ نمونه داده‌ها و تنظیمات فعلی را جدا نگه دارید.
2. ماژول پل `0.1.7` را در پرفکس نصب و فعال کنید (بدون تغییر مسیرهای API موجود).
3. بسته نصبی ویندوز `0.2.5` را نصب کنید.
4. برنامه را باز و به API با کلید دستگاه قبلی متصل کنید.
5. در تنظیمات، نشانی HTTPS پنل وب را ثبت کنید؛ اگر صفحه وب روی زیردامنه دیگری اجرا می‌شود، همان دامنه را وارد کنید.
6. از منو بخش فروش، حسابداری یا انبار را باز کنید و «باز کردن فرم عملیاتی واقعی» را بزنید.
7. داخل پنجره امن وب با حساب کاربری دارای مجوز وارد شوید؛ عملیات مالی در همان سامانه اصلی ثبت می‌شود.

## محدودیت‌های آگاهانه
- این **نسخه کامل بومی تمام فرم‌های ثبت** نیست؛ فرم‌های تراکنشی تا زمان ساخت APIهای امن و فرم‌های مستقل WPF از طریق WebView2 اجرا می‌شوند.
- عملیات مالی آفلاین پیاده‌سازی نشده است و نباید هنگام قطع اتصال قطعی تلقی شود.
- این نسخه هیچ مسیر POST مالی در API کلید دستگاه اضافه نمی‌کند؛ مجوز، CSRF و اعتبارسنجی همان وب باید برقرار باشند.
- اگر ورود HTTPS به پرفکس خطای 419 بدهد، پنل عملیاتی هم باید تا اصلاح نشست/HTTPS از ثبت عملیات خودداری کند.
- صحت دریافت و ثبت داده روی هاست و دستگاه واقعی باید توسط مدیر سامانه آزمایش شود.
